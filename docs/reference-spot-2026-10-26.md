# Default scoring and reference spot test, 2026-10-26

The default already selects the canonical cube-root metric, SIMD dispatch,
and full-image evaluation. `Ssimulacra2Config::simd()` is a convenience alias
for `Default`; it does not select a different metric or a C++ backend.
The two public kernel choices are `Scalar` and `Simd`. Dispatched tiers are
AVX2/FMA, NEON, WASM SIMD128 and scalar fallback. Rayon optionally parallelizes
work within that metric.

## Measured limits

Cloudinary and libjxl are not interchangeable HDR oracles in this test.
They agree exactly on 12 of 20 pairs and differ on 8: both sizes of linear
BT.2020, PQ BT.2020 RGB/RGBA, and HLG BT.2020 RGB. HLG grayscale agrees.
The experiment does not isolate the differing CMS/XYB implementation step.

Fast-ssim2 agrees with Cloudinary on 14 of 20 pairs: both opaque RGB8 sRGB
cases, both linear BT.709 cases, and all ten native wide-gamut/HDR cases.
The remaining six are fractional-alpha RGBA8 sRGB and RGB16/f32 sRGB at both
sizes, which use the existing polynomial conversion without a bit-equality
contract. This test does not establish universal reference equality.
Default, explicit scalar, explicit SIMD and cached-default Rust scores agree
exactly on all 20 pairs. The committed native-HDR regression suite also checks
the bare default and cached-default entry points against the existing captures.

## Reduced-RAM strips

The strip scorer remains implemented and opt-in. It bounds intermediate blur
and metric buffers with row strips and halos, while input conversion still
materializes full-image buffers. Cached comparisons retain the reference
pyramid. It is not a decoder-to-score streaming API.

Strip scores can differ because recursive-blur warmup and reduction order
change. With 64 interior rows and the default 96-row halo, the 513×257 opaque
RGB8 pair changes from 93.529528546307915 to 93.530301771157824. Native HDR
still rejects strip configuration. This experiment measures score differences,
not peak-memory savings; it does not provide memory-complexity bounds for total
storage. Keeping strips opt-in preserves the reference-order default.

## Provenance and reproduction

The library implementation is commit `31dfc0d57b96174d2dc75973eebedb74ec2f6dc5`;
this audit changes only instrumentation, regression coverage and documentation.
The tested instrumentation landed as `508b79874de00549ffe71e24de8044cdf51887bc`.
The runner is [reference_spot.rs](../fast-ssim2/examples/reference_spot.rs).
It generates deterministic noise and constant patches at 17×13 and 513×257,
adds a fixed encoded-sample perturbation, and preserves both PNGs under the
requested new output directory. Float cases use the same quantized sample grid
as their 16-bit PNG representation. It uses profiles generated by the pinned
Cloudinary color encoder in the raw oracle's `profile` mode.

The raw oracle receives exact normalized f32 bits; the two CLI tools receive
identical PNGs with the same embedded ICC profiles. Raw Cloudinary and
Cloudinary's PNG CLI agree exactly on all 20 pairs, controlling for file decode
in this experiment. Alpha cases use the worst of encoded-domain 0.1/0.9
backgrounds in all three implementations.

- [Cloudinary SSIMULACRA2](https://github.com/cloudinary/ssimulacra2/tree/81feacf6a5b0bbd7ec11b4a881a4615033ab0b10):
  `81feacf6a5b0bbd7ec11b4a881a4615033ab0b10`, with its bundled libjxl,
  lcms2 2.12 and Highway 1.2.0. The raw oracle SHA256 is

  byte-identical `tools/ssimulacra2.cc` to the release. Other libjxl dependencies
  were not compared exhaustively, and main was not runtime-tested here.

Both original C++ CLIs print only eight decimal places. The
[precision-copy helper](../tools/reference_cli_precision.py) preserves each
original and changes only the unique six-byte score format from `%.8f\n\0`
to the equal-length `%.17g\0` in a new executable. No arithmetic bytes change.
The helper records original/copy hashes and offset in adjacent JSON. All 20
original CLI outputs equal the precision-copy scores rounded to eight decimal
places, for both tools. Capture headers identify the precision-copy hashes.

```sh
just build-native-hdr-oracle CLOUD_SOURCE CLOUD_BUILD NEW_RAW_ORACLE
just reference-cli-precision CLOUD_CLI NEW_CLOUD_17G
just reference-cli-precision LIBJXL_CLI NEW_LIBJXL_17G
just reference-spot NEW_RAW_ORACLE NEW_CLOUD_17G NEW_LIBJXL_17G NEW_OUTPUT_DIR
```

Run builds and the experiment through the normal resource wrapper, serialize
heavy commands, and supply new paths to preserve previous artifacts. Runtime
scope is x86-64 GNU Linux; this does not establish cross-libm f64 equality.
The successful 10-second run reported peak RSS 0.26 GiB, minimum available
memory 9572 MiB and peak load 3.70 from `run-heavy`; those are wrapper observations
for this small correctness run, not an isolated library-memory benchmark.
